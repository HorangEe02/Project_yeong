# 기능 구현 문서: 녹음 및 업로드

## 목표

사용자가 iPhone, Android, MacBook, Windows 노트북, 블루투스 이어폰 마이크로 회의를 녹음하고, 녹음 파일을 Mac 로컬 Worker에 업로드해 처리 job을 생성한다.

MVP에서는 네이티브 앱보다 웹 클라이언트를 우선한다. 웹 클라이언트는 모바일 브라우저와 데스크톱 브라우저에서 동작해야 하며, 브라우저 녹음이 불안정한 기기에서는 기존 녹음 파일 업로드를 허용한다.

## 사용자 흐름

1. 사용자가 회의 제목을 입력한다.
2. 녹음 소스 권한을 허용한다.
3. 녹음을 시작, 일시정지, 재개, 종료한다.
4. 종료 후 녹음 길이와 파일 크기를 확인한다.
5. 사용자가 업로드를 누르면 `POST /v1/jobs`로 파일과 메타데이터를 전송한다.
6. 서버는 원본 파일을 저장하고 `uploaded` 상태의 job을 만든다.
7. UI는 job 상태를 polling하거나 server-sent events로 갱신한다.

## 입력 포맷

| 구분 | 허용 포맷 | 비고 |
| --- | --- | --- |
| 모바일 원본 | `m4a`, `aac`, `webm` | 브라우저와 OS별 실제 지원 포맷 차이를 허용 |
| 데스크톱 원본 | `webm`, `wav`, `m4a` | 웹 녹음은 `webm` 가능성이 높음 |
| ASR 처리용 | `wav` | Worker가 16kHz mono 또는 모델 권장값으로 변환 |
| 내보내기 | `mp3`, `m4a`, `wav` | MVP는 텍스트 내보내기를 먼저 구현 |

## 클라이언트 구현 기준

- `MediaRecorder` 지원 여부를 먼저 감지한다.
- 지원하지 않는 브라우저에서는 파일 업로드 모드만 표시한다.
- 녹음 중에는 경과 시간, 입력 레벨, 저장 예상 크기를 표시한다.
- 업로드 전 최소 길이와 최대 크기를 검사한다.
- 사용자가 브라우저를 닫아도 원본 Blob을 복구할 수 있도록 IndexedDB 임시 저장을 고려한다.
- MVP에서는 실시간 스트리밍 전사를 하지 않고 녹음 완료 후 일괄 업로드한다.

## 업로드 요청

`POST /v1/jobs`

`multipart/form-data`

| 필드 | 필수 | 설명 |
| --- | --- | --- |
| `audio_file` | 예 | 원본 녹음 파일 |
| `title` | 아니오 | 회의 제목. 없으면 녹음 날짜 기반 자동 생성 |
| `recorded_at` | 예 | ISO 8601 녹음 시작 시각 |
| `duration_ms` | 아니오 | 클라이언트가 측정한 녹음 길이 |
| `source_device` | 아니오 | `iphone`, `android`, `macbook`, `windows`, `bluetooth_mic` 등 |
| `language` | 아니오 | 기본값 `ko` |
| `hotwords` | 아니오 | 제품명, 참석자명 등 ASR 보정 힌트 |

## 서버 처리

1. 파일 확장자와 MIME type을 검사한다.
2. 파일 크기, 길이, 샘플레이트를 검사한다.
3. 원본 파일을 `/users/{user_id}/meetings/{meeting_id}/original.{ext}`에 저장한다.
4. `meetings`, `recording_files`, `jobs` 레코드를 생성한다.
5. background queue에 `normalize_audio` 작업을 넣는다.
6. 응답으로 `job_id`, `meeting_id`, `status`를 반환한다.

## 실패 처리

| 오류 | HTTP | 사용자 메시지 |
| --- | --- | --- |
| `unsupported_media_type` | 415 | 지원하지 않는 녹음 파일입니다. m4a, aac, webm, wav 파일을 사용하세요. |
| `file_too_large` | 413 | 파일이 너무 큽니다. MVP 제한보다 짧은 녹음으로 다시 시도하세요. |
| `audio_too_short` | 422 | 녹음 길이가 너무 짧아 회의록을 만들 수 없습니다. |
| `storage_write_failed` | 500 | 원본 파일 저장에 실패했습니다. 다시 시도하세요. |

## 완료 조건

- 모바일 웹과 데스크톱 웹에서 녹음 또는 파일 업로드가 가능하다.
- 업로드 성공 시 job이 생성되고 `uploaded` 상태가 반환된다.
- 원본 음성 파일이 저장 경로에 보존된다.
- 업로드 실패 원인이 사용자에게 구분되어 표시된다.
- 같은 파일 재업로드 시 중복 job 생성을 막거나 사용자가 명시적으로 새 회의로 생성할 수 있다.
