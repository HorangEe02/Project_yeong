# Figma as-built 동기화 이력

- **대상**: 디자인 시스템 Figma 파일 `LN 00 ~ LN 09` / 기준 코드 `local-worker/web/`
- **원칙과 절차**: [design-system-figma.md §8](design-system-figma.md#8-as-built-동기화--코드가-바뀌면-figma-를-따라-고친다)

이 파일은 **무엇을 언제 왜 고쳤는지**의 기록이다. 규칙은 본 문서 §8 에 있고,
여기에는 그 규칙이 나오게 된 근거가 남는다. 갱신할 때마다 아래에 차수를 덧붙인다.

---

### 1차 갱신 (2026-07-29) — 구현 반영

구현된 3건을 반영했다 — 목록 우측 녹음 길이 · FAB 하단 중앙 64px · 선택 모드.

| 대상 | 내용 |
|---|---|
| LN 04 회의 카드 | 날짜줄에서 길이 제거, 우측에 `45:30`(`ink/500` 11px) 추가 |
| LN 04 FAB | `56×31` + `+` 텍스트 → `64×64` 원형 + `index.html:72` plus SVG |
| LN 05 FAB 위치 | 5개 화면 `(318, 708)` → `(163, 708)` |
| LN 05 M-01 헤더 | 벨 · 선택 · 새 회의 버튼 추가 |
| LN 07 | 영향받은 7장 재캡처(모바일 5 · 웹 2), 나머지 7장 유지 |

**함께 드러난 기존 누락 2건**

- 마이페이지·알림함에 FAB 가 없었다. `.tab-fab` 은 `new`·`detail` 에서만 숨으므로 이 두 화면에도
  떠야 한다.
- M-01 헤더에 우측 버튼군(벨·새 회의)이 통째로 없었다. 선택 버튼만 넣으면 카운트 옆에 붙어
  실제와 다른 자리가 되므로 셋 다 넣었다.

둘 다 이번 코드 변경과 무관한, 처음부터 있던 차이다. 화면을 손대는 김에 실측과 대조해서
드러났다 — §6 의 팔레트 대조와 같은 성격이다.

### 제안 페이지에 구현 상태를 적을 때는 코드를 읽는다

LN 09 주석에 *"상세 요약: `summary_versions` 에 타임스탬프가 없다. 스키마·프롬프트 변경이
필요하다"* 라고 적어뒀는데 **사실이 아니었다.** `summary_sections` 의 `start_ms`·`end_ms` 는
「타임스탬프 앵커 구간 요약」부터 있었고, 제공자가 전사 구간의 실제 시각을 붙여 저장하며
프런트는 시각 칩으로 그 지점부터 재생까지 한다.

실제 차이는 **위치뿐**이었다 — 요약이 오프캔버스 드로어 안에 있어 `#/meetings/{id}/summary`
로 들어와도 전사가 보였다. URL 이 탭을 가리키면 드로어를 열도록 한 프런트 10줄로 끝났다.

화면을 보고 "이 기능은 없다" 고 넘겨짚은 게 원인이다. 주석은 나중에 일정 산정의 근거가 되므로
**구현 상태는 반드시 코드에서 확인하고 적는다.** 해당 주석은 「구현 결과」로 다시 썼다.

### 2차 갱신 (2026-07-29) — 치수 감사

LN 09 를 스크린샷으로 점검하다 **탭바가 실제보다 8px 두꺼운 것**을 발견했고, 원인을 좇으니
목록·카드 전반의 치수가 어긋나 있었다. §1~§7 은 전부 **색** 작업이었다. 색은 팔레트 대조로
끝까지 훑었지만 **치수는 아무도 재지 않았다** — 색 감사를 통과했다고 치수가 맞는 게 아니다.

기준값은 프로덕션 앱을 390×844 로 열어 `getBoundingClientRect` · `getComputedStyle` 로 떴다.
LN 07 캡처와 같은 환경이라 `env(safe-area-inset-bottom)` 은 0 이다.

#### 탭바 — 컴포넌트 하나가 10개 화면을 밀고 있었다

`탭바 / 홈 선택` 이 64px 였다. 내부는 패딩 8 + 콘텐츠 39 + 8 = 55 인데 `counterAxisSizingMode`
가 FIXED 64 라 9px 이 붕 떠 있었다. CSS 는 `height: calc(56px + env(safe-area-inset-bottom))` 이고
실측도 56 이다. 64 는 56 도 90(56+34)도 아니라 어느 해석으로도 설명되지 않는다.

| | 실제 빌드 | 이전 | 이후 |
|---|---|---|---|
| 탭바 | `y 788 · h 56` | `y 780 · h 64` | `y 788 · h 56` |
| FAB | `x 163 · y 708` | LN 05 708 / LN 09 **700** | 708 |
| FAB↔탭바 | 16 | LN 05 8 / LN 09 16 | 16 |

증상은 페이지마다 달랐지만 원인은 하나였다. LN 05 는 FAB 절대 위치가 맞는 대신 간격이 좁았고,
LN 09 는 간격을 맞추다 탭바의 오차를 흡수해 위치가 틀어졌다.

높이 56 + `counterAxisAlignItems: CENTER`(자식 y=8.5 — 빌드의 `.tab-btn { justify-content: center }`)
로 고치고, 인스턴스 10개를 `y 780→788`, `스크롤` 프레임을 `780→788` 로 맞췄다. **화면 프레임은
`layoutMode: NONE`(절대 배치)이라 컴포넌트를 고쳐도 인스턴스 y 는 따라오지 않는다.**

#### 회의 카드 — 잘못된 값들이 서로 상쇄돼 있었다

카드 높이가 91 로 빌드(91.3)와 맞아 보였는데, 타이포를 고치자 92 가 됐다. 맞아 보이던 91 은
**틀린 값들이 우연히 상쇄된 결과**였다.

| 항목 | 이전 | 이후 | 빌드 |
|---|---|---|---|
| 제목 | 13.5 · `ink/900` | 14 · `ink/950` | 14 / 700 / `#0F1222` |
| 날짜 | 11.5 | 12 | 12 |
| 행높이 | AUTO (17 / 14) | 155% (22 / 19) | 21.7 / 18.6 |
| 패딩 | 14 / 14 | 11 / 10 | `11px 10px` |
| 아바타 | 40 | 42 | 42 |
| 아바타↔본문 | 12 | 11 | 11 |
| 제목↔날짜 | 6 | 2 | 2 |
| 날짜↔칩 | 6 | 7 | 7 |
| 칩 높이 · 간격 · 좌우패딩 | 21 · 6 · 9 | 20 · 5 · 8 | 20 · 5 · 8 |
| 카드 폭 | 360 | 369 | 369 |

빌드 구성은 `11 + 21.7 + 2 + 18.6 + 7 + 20 + 11 = 91.3` 이다. Figma 의 세로 auto-layout 은
gap 이 하나뿐이라 2 와 7 을 동시에 낼 수 없어, `본문` gap 을 2 로 두고 `태그` 프레임에
`paddingTop: 5` 를 얹어 7 을 만들었다.

#### 목록 컨테이너 — 패딩이 컨테이너마다 다르다

Figma 는 15/20/18 로 뭉뚱그려져 있었는데 CSS 는 화면마다 다르다.

| 화면 | 이전 | 이후 | CSS |
|---|---|---|---|
| M-01 홈 | 15 | 10 | `.list-scroll` `4px 10px` |
| M-02·03·04·튜토리얼 | 20 | 16 | `.compose-scroll` `18px 16px` |
| 폴더 | 18 | 18 ✓ | `.folder-page` `20px 18px` |
| 마이 · 알림 | 18 | 16 | `.mypage/.notif-page` `18px 16px` |
| 달력 | 18 | 14 | `.cal-page` `18px 14px` |

M-01 스크롤은 **389** 로 줄이고 우측에 1px `border/base` 스트로크를 넣었다 —
`.col-list { border-right: 1px }` 때문에 내용 폭이 390 이 아니라 389 이고, 그래야
`389 − 10 − 10 = 369` 가 나온다. 홈 배너는 `margin: 4px 8px 12px` 라 353 이므로 고정폭으로
빼고 스크롤을 가운데 정렬했다(FILL 자식은 정렬과 무관하게 꽉 차므로 나머지는 영향 없음).

#### LN 06 웹 목록 — 한 줄이었다

`제목` / `날짜 · 길이` 한 줄 구조에 6개 항목이 전부 `45:30` 이었다. 빌드는 모바일과 같은
`listItemHtml` 을 써서 2줄이다.

```
[아바타] 제목 ───────────── 45:30      .list-item-top (flex, baseline, gap 8)
         2026.07.27 (월)                .list-item-sub (margin-top 2)
```

항목 12개(2화면 × 6)를 재구성하고 타이포를 실측값(14/`ink/950` · 11/`ink/500` · 12/`ink/500`)에
맞췄다. 제목을 FILL(`flex:1`), 길이를 HUG(`flex:none`)로 둬 길이가 우측 끝에 붙는다.

#### 절대배치가 두 번 발목을 잡았다

- **길이 텍스트.** 좌표 고정이라 `1:02:40` 처럼 자릿수가 늘면 오른쪽으로 밀려 카드 밖으로
  나갔다. 폭 60 고정 + 우측 정렬로 바꿨다. 카드 폭이 360→369 로 커졌을 때도 좌측 앵커(`MIN`)라
  여백이 19 가 됐다 — 제약을 `MAX` 로 바꿔 폭과 무관하게 10 을 유지한다.
- **아바타 이니셜.** 화자별 색이 달라 카드 컴포넌트 밖 절대배치 텍스트로 얹혀 있다. 원의
  크기·위치가 바뀔 때마다 따라오지 않아 세 번 재정렬했다. 원의 `absoluteBoundingBox` 를 읽어
  그대로 씌우는 방식이 확실하다.

#### LN 09 카드는 인스턴스가 아니었다

컴포넌트를 고치면 LN 05·LN 09 양쪽에 전파될 것으로 봤는데, LN 09 의 카드는 **분리된 프레임**
이라 전파되지 않았다(제안을 만들며 구조를 바꾸느라 detach 했다). 같은 값을 직접 넣어야 했다.
**전파를 전제하기 전에 `type === 'INSTANCE'` 를 확인할 것.**

#### 탭바 활성 탭 — 9화면 중 8화면이 홈을 켜고 있었다

탭바가 변이 없는 **단일 컴포넌트 `탭바 / 홈 선택`** 이라 인스턴스 10개가 전부 같은 상태였다.
폴더 화면에서도, 달력 화면에서도, 마이페이지에서도 홈이 켜져 있었다. 색 자체는 맞았다 —
활성 `brand/700` · 비활성 `ink/400` 으로 `.tab-btn.is-active` 와 일치한다. 틀린 건 **어느 탭이
켜지느냐** 였다.

```js
// app.js:695-700
document.querySelectorAll('[data-nav]').forEach(a => a.classList.remove('is-active'));
var map = { list:'home', detail:'home', calendar:'calendar', folders:'folders', me:'me' };
var key = map[route.name];
if (!key) return;   // ← 제거를 먼저 하고 반환한다
```

`new` 와 `notifications` 는 map 에 없다. **이전 탭이 유지되는 게 아니라 아무 탭도 안 켜진다** —
제거가 반환보다 앞이기 때문이다.

속성 `활성` 5종(`홈`·`폴더`·`달력`·`마이`·`없음`)의 변이 세트로 바꾸고 라우트대로 지정했다.

| 화면 | 라우트 | 변이 |
|---|---|---|
| M-01 홈 | `list` | 홈 |
| M-02 · M-03 · M-04 · 튜토리얼 | `new` | 없음 |
| M-07 달력 | `calendar` | 달력 |
| 폴더 | `folders` | 폴더 |
| 마이페이지 | `me` | 마이 |
| 알림함 | `notifications` | 없음 |
| M-05 · M-06 · M-06b | `detail` | (탭바 숨김) |

변이 세트가 되면서 LN 04 의 섹션 프레임이 145 → 417 로 커져 아래 두 섹션을 덮었다. 이 페이지의
관례(섹션 프레임 안에 `제목·설명·샘플`, 변이 세트는 **형제**로 아래, 그 밑에 `▲ Variant Set` 주석)에
맞춰 세트를 밖으로 빼고 샘플·주석을 더한 뒤 아래 4개 섹션을 원래 간격(48·19·52·28)대로 옮겼다.

### 3차 갱신 (2026-07-29) — LN 06 검증에서 파생

LN 06 자체는 대부분 정확했다. 빌드 그리드 `72px 320px 712px 336px` 와 정확히 일치하고, 테두리
(레일·목록 우측 1px, `col-right` **좌측** 1px, `col-center` 없음), 레일 활성(`brand/100` +
`brand/900`), 활성 목록 항목(`brand/50` + `brand/700`), W-02 의 사용법 패널까지 전부 맞았다.

문제는 **LN 06 과 LN 05 가 서로 달랐다**는 것이다. 같은 `.list-item` 인데 LN 06 은 평면 행,
LN 05 는 카드였다. 둘 다 맞을 수는 없다.

#### 회의 카드는 카드가 아니었다

```css
.list-item { background: transparent; border: none; border-radius: var(--radius-md); }
.list-item:hover     { background: var(--surface-alt); }
.list-item.is-active { background: var(--brand-50); }
```

배경은 hover·선택 때만 생긴다. 프로덕션 390 스크린샷으로도 확인했다 — 아바타·제목·날짜·칩이
페이지 배경 위에 그냥 얹혀 있다. 그런데 컴포넌트는 `surface/surface` 채움 + `border/base` 1px
테두리를 갖고 있었다. **LN 06 이 맞고 LN 05 가 틀렸다.** 컴포넌트에서 둘 다 제거했고
(LN 09 분리 카드 4장은 직접), 라운드 12 는 남겼다 — 빌드에도 있고 hover·선택 때 보인다.

같은 착각이 LN 09 주석에도 있었다. 「참고의 평면 행(카드 없음)은 적용하지 않았다」고 적어뒀는데
앱은 **이미 평면 행**이라 참고 UI 와 다르지 않았다. Figma 목업을 앱으로 착각한 것이다.

#### 유령 클래스 2건 — 노드명에 없는 클래스를 적어뒀다

이 파일은 노드명에 CSS 클래스를 적는 관례다. 그런데 두 개는 코드에 존재하지 않았다.

| 노드명 | 실재 | 실제 클래스 |
|---|---|---|
| `오디오 바 · .audio-bar` (LN 05 3화면) | `index.html`·`styles.css`·`app.js` 통틀어 **0건** | `.playback-bar` |
| `헤더 · .detail-head` (LN 05 3화면) | `.cal-day-detail-head`(달력용)만 존재 | `.detail-topbar` |

없는 클래스를 근거로 구현하려 하면 그 자리에서 막힌다. **노드에 클래스명을 적을 때는 grep 으로
실재를 확인한다.**

#### W-01 에 검색 행과 재생 바가 없었다

실제 데스크톱 상세의 `col-center` 는 `detail-topbar 82` + `msg-list-wrap 721`
(안에 `transcript-search-row 57`) + `playback-bar 97` = 900 이다. LN 06 엔 헤더와 전사뿐이었다.
둘을 실측 사양대로 만들고 전사를 FILL 로 바꿔 재생 바가 바닥(y803)에 붙게 했다.

#### 모바일 상세 3화면 (M-05 · M-06 · M-06b)

| 요소 | 이전 | 이후 | 빌드 |
|---|---|---|---|
| 상단바 패딩 | `16/16/14/16` | `14/20` | `14px 20px` |
| 하단 테두리 | 없음 | 1px `border/base` | `border-bottom: 1px solid var(--border)` |
| 뒤로가기 | 아이콘 24 만 | 32×32 버튼 박스 | `.detail-back-btn` 32×32 r8 |
| 제목 | 15px | 17px / Bold | `.title-edit-input` 17px/800 |
| 메타 | 블록에 직접, gap 7 | `.detail-meta` 랩 행 gap 10, 날짜 12px | `margin-top 4 · gap 10 · wrap` |
| 액션 버튼 | 34×24 gap 8 | 34×34 gap 6 | gap 6 |
| 검색 행 | 390×52 `12/16/6/16` 입력 310×34 | 390×57 `12/20/4` 입력 280×41 | 동일 |
| 재생 바 | 390×112 @ y732 | **390×145 @ y699** | 동일 |

재생 바는 구조가 달라 다시 만들었다. 빌드의 `.playback-row` 는 **랩된다** — 350px 폭에 버튼
3개(36·44·36)와 배속 65 가 들어가면 `.playback-seek-wrap` 이 다음 줄로 밀린다. 그래서
`12 + now 19 + 8 + (44 + 8 + 40) + 14 = 145` 다. `재생 대기 중` 줄도 빠져 있었다.
세 화면 모두 `93 + 57 + 549 + 145 = 844` 로 재배치했고, 드로어 화면은 자식 순서를 지켜
딤·드로어가 재생 바 위에 남게 했다.

**총높이로 비교하면 안 되는 경우가 있다.** 처음엔 "상단바가 96 인데 빌드는 140" 이라고 봤는데,
빌드의 140 은 **제목이 180px 폭에서 줄바꿈해 생긴 값**이다(`.detail-topbar-main` 이 111).
프로덕션 제목은 `회의 2026-07-29`, 목업은 `제품 MVP 킥오프` 라 길이가 다르다. 높이를 140 으로
맞추는 대신 요소별 사양을 맞추고 프레임이 hug 하게 뒀다(→ 93).

### 4차 갱신 (2026-08-04) — LN 09 제안을 코드로 반영

지금까지는 **Figma 를 코드에 맞추는** 방향이었다. 이번은 반대다 — LN 09 에 남아 있던 제안 중
아직 코드에 없던 것을 확인해 구현했다(PR #61, 프런트 전용).

#### 확인 — 5건이 미구현이었다

| 제안 | 근거 |
|---|---|
| 목록 제목 34px | `.list-header-title` 19px / 모바일 17px |
| 전사 위 인라인 요약 | `구간 요약` 은 드로어 요약 탭 안에만 |
| AI 면책 문구 | `app.js`·`index.html`·`styles.css` 통틀어 **0건** |
| 화자·길이·발화 수 한 줄 | `.detail-meta` 는 배지·날짜·길이만 |
| FAB 아이콘 | `＋` SVG + `aria-haspopup="menu"` |

#### 반영한 것

- **목록 제목 34px — 헤더 2줄.** 모바일에서 제목을 키우면 벨·선택·＋ 와 한 행에 못 둔다.
  액션이 윗줄, 제목이 아랫줄(iOS large title 관례). 데스크톱은 `order` 로 다시 한 줄이라
  DOM 은 하나만 유지한다.
- **전사 위 상세 요약.** 드로어가 쓰던 `summaryState.sections` 를 그대로 쓰고, 시각 칩도 같은
  `data-action="seek-section"` 이라 `centerEl` 의 기존 `handleAction` 이 받는다.
- **AI 면책 문구.** 상세 요약 아래. `ICONS` 에 `info` 추가.
- **화자 수·발화 수.** `.detail-meta` 에 더했다. 전사 로드 후에야 알 수 있어
  `renderSpeakerList` 에서 채운다.

#### FAB 는 제안대로 다 할 수 없었다

아이콘은 `＋` → 녹음 점으로 바꿨지만 **바로 녹음하지는 않는다.** 기존 2항목 메뉴의 두 항목이
하는 일이 똑같이 `#/new` 이동이었는데, `app.js` 주석에 그 이유가 적혀 있다 — 자동으로 녹음을
시작하거나 파일 선택창을 열면 권한 프롬프트가 뜨고, **동의 체크 전에 캡처가 시작되며**,
`hashchange` 를 거치며 제스처 창을 벗어난다.

그래서 메뉴만 없애고 녹음 화면으로 보낸다. 파일 업로드는 그 화면의 드롭존에 그대로 있다.
`pendingComposeIntent` 는 이걸로 죽어서 걷어냈다.

**제안을 그대로 적용할 수 없을 때는 제약을 기록에 남긴다** — 다음에 같은 제안을 다시 꺼내
같은 벽에 부딪히지 않게.

#### 잡은 회귀 1건

2줄 헤더에서 **벨만 왼쪽으로 떨어졌다.** `.list-bell-btn` 과 `.list-select-btn` 이 각자
`margin-left: auto` 를 갖고 있었다(한 줄 헤더 시절 우측 정렬용). 정렬은 이제
`.list-header-actions` 가 하므로 둘 다 제거. 스크린샷이 아니라 계산된 `margin-left: 222px` 를
읽고 찾았다.

#### 남은 것

`12개 발화` 가 `.detail-meta` 와 `.transcript-search-row` 두 곳에 나온다. LN 09 목업도 그렇지만
실제 화면에선 중복으로 읽힌다.

**LN 05·06·09 의 as-built 반영은 아직이다.** 이번 코드 변경(헤더 2줄·상세 요약·FAB)이
Figma 화면에 들어가야 하고, §8 절차 3에 따라 LN 07 재캡처 여부도 다시 판정해야 한다.

### 5차 갱신 (2026-08-04) — as-built 반영 + LN 07 전면 재캡처

4차(코드)를 Figma 로 되돌린 차수다. **as-built 는 배포된 화면을 기록하는 것**이라, 옮기기 전에
빌드가 맞는지부터 확인했고 그 과정에서 코드 결함 2건이 나왔다.

#### 옮기기 전에 빌드를 고쳐야 했다

| PR | 내용 |
|---|---|
| #63 | `<ol>` UA `padding-left: 40px` — 시각 칩이 머리말보다 40px 오른쪽에 있었다 |
| #64 | `<ol>` UA `margin-block: 1em` — **CSS 에 적은 간격이 실제로 적용되지 않고 있었다** |

#64 가 특히 그렇다. 머리말 아래 `8`, 면책 위 `10` 으로 적어뒀는데 실제로는 둘 다 14.5 였다.
`<ol>` 의 UA margin 이 이웃과 상쇄되며 이겼기 때문이다. 블록 높이가 계산값 167 이 아니라 180 인
것을 보고 찾았다 — **화면으로는 못 잡는다.** 13px 은 "좀 넓네" 로만 보인다.

#63 이 절반만 고친 것이기도 하다. `padding` 을 지웠으니 됐다고 봤는데 `margin` 이 남아 있었다.

#### LN 07 재캡처 — 이제 재현 가능하다

`web/` 에 시각 변경(#61·#63·#64)이 있어 §8 절차 3의 게이트를 통과했다. 절차 4대로 시드
스크립트를 먼저 만들었다(`scripts/seed_demo.py`) — LN 05·06 목업과 **같은 6건**을 만든다.

캡처는 CDP 2x. 만들면서 걸린 것들:

- **해시만 다른 이동은 `Page.navigate` 로 안 걸린다.** 홈을 경유하고 `location.hash` 로 바꿔야
  `hashchange` 가 난다. 드로어 2장이 이것 때문에 안 열렸다.
- **녹음 중**은 `getUserMedia` 를 `AudioContext`→`createMediaStreamDestination` 가짜 스트림으로
  덮어 잡는다. 00:06 · 녹음 중 배지 · 레벨 미터까지 나온다.
- **처리 중**은 정지만으로는 '완료' 미리듣기까지다. `#nm-upload-btn` 을 눌러야 스텝퍼가 뜬다.
  서버를 `STUB_STAGE_DELAY=1.6` 으로 띄워 중간을 잡는다.
- **투어**는 `maybeStartTour()` 가 부팅 끝에서 한 번만 돌아 `location.reload()` 가 필수다.
  키는 `ln.tour-seen`.
- **녹음·처리는 반드시 맨 마지막.** 회의를 1건 더 만들어 목록이 6→7 이 된다. 처음엔 중간에
  찍어서 데스크톱 2장만 7건이 됐다 — 데이터가 갈리면 대조 기준이 깨진다.

`upload_assets` 는 저장소에만 올리고 캔버스 배치를 안 한다. `imageHash` 가 PNG 의 SHA-1 이라
로컬에서 계산해 `fills` 로 직접 지정했다(14장 전부 업로드 응답 해시와 일치).

#### 사고 1건 — 리포 DB 오염

DB 경로 변수를 `SQLITE_PATH` 로 잘못 줬고, **조용히 무시돼 이번 세션의 검증 데이터 13건이
리포의 `local-worker/data/app.db` 에 쌓였다**(올바른 이름은 `DB_PATH`). 미러에는 `data/` 가
rsync 제외라 안 넘어갔고, 사용자의 기존 6건(2026-07-16~17)과는 `created_at` 으로 구분된다.
정리는 별도 확인 후 진행한다.
