# UI 패리티 프로그램 — 결과 기록

- **기간**: 2026-07-24 ~ 2026-07-26
- **상태**: 완료 (서브프로젝트 A~G 전부 구현·배포)
- **대상**: `local-worker/web/` 프런트엔드 + `local-worker/app/` 백엔드

## 목표

회의 녹음 앱을 참고 디자인 8개 화면 기준으로 재정비했다. 1:1 클론이 아니라
데모에 실체가 있는 기능만 골라 번안하고, 실체 없는 항목(연결 기기·프로모션 쿼터 등)은
제외하거나 정직하게 비활성 처리하는 방침을 유지했다.

## 프레이밍 결정

1. **반응형 통합.** 760px 미만은 하단 탭바(홈·폴더·달력·마이) + FAB, 이상은 기존 아이콘 레일.
   뷰 렌더 로직은 공유하고 내비 크롬만 CSS로 스위치한다.
2. **최대 실기능.** 폴더·휴지통·공유 분류·알림 인박스·마이 설정을 실제 백엔드(SQLite + Postgres 이중 지원)로 동작시킨다.
3. **테마 혼합.** 구조·컴포넌트 패턴만 참고하고 포인트 컬러는 기존 옐로(`#FFC700`)를 유지해
   기존에 검증한 WCAG 대비를 재작업하지 않는다.

## 프로그램 중 확정된 설계 결정

- **폴더**: 노트는 폴더 하나에만 속한다(단일 `folder_id`). 휴지통 자동 영구삭제는 없고 수동 비우기만 지원한다.
  "공유받은/공유한"은 폴더가 아니라 뷰로 다룬다.
- **마이페이지**: 사용량 도넛은 실수치 **표시용**이며 쿼터를 강제하지 않는다.
  관심 분야는 저장만 하고 요약·분류에는 영향을 주지 않는다.
- **알림**: 알림 본문은 별도 테이블에 쓰지 않고 `audit_logs`에서 파생한다.
  읽음/숨김 같은 사용자별 상태만 `notification_states`에 저장한다(`read_at`).
- **튜토리얼**: FAB는 2액션(녹음 시작·파일 업로드)이다.
  녹음 중 화면을 벗어나려 하면 확인 다이얼로그로 막는다.
  코치마크 투어는 모바일 `#/new`에서 최초 1회만 뜨고(`localStorage`), 데스크톱은 우측 팁 패널이 같은 역할을 한다.

## 구현 중 배운 것 (재발 방지)

- **이중 DB 차이**: SQLite는 `IN ()`을 허용하지만 Postgres는 문법 오류다. 빈 목록은 SQL이 아니라 Python 쪽에서 걸러야 한다.
- **모바일 레이아웃**: 목록 컬럼을 숨기는 규칙이 라우트 허용 목록 방식이라, 라우트를 새로 추가하면 반드시 그 목록에도 넣어야 한다. 빠뜨리면 375px에서 화면이 반씩 갈린다.
- **설정 PATCH**: 서버가 최상위 키만 병합하므로 부분 전송은 다른 토글을 지운다. 항상 전체 키를 보낸다.
- **`position: fixed` 자식**: 부모에 `transform` 애니메이션이 걸리면 그 부모가 컨테이닝 블록이 되어 좌표가 어긋난다. 스포트라이트 오버레이에는 transform을 쓰지 않는다.
- **`<dialog>`의 `close` 이벤트**: 큐잉되는 비동기 이벤트라 일부 셸 환경(Electron 기반 브라우저 등)에서 유실된다.
  확인 다이얼로그는 버튼 핸들러에서 직접 resolve 하고, `close`·`cancel` 이벤트는 ESC 등 나머지 경로용 보조로만 쓴다.
