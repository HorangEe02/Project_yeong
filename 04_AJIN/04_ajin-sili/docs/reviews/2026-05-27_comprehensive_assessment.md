## 1️⃣ 실리 경진대회 취지 부합도

### ✅ 강점 — "실리(實利)"의 본질 충족

1. **실제 운영 가능한 자가 호스팅 하이브리드 아키텍처**
   Cloud Run + Cloudflare Tunnel + 로컬 Ollama 조합. *사내 데이터를 외부 LLM에 흘리지 않는* 구조를 실증함. `ajin-cb.web.app` 라이브 가동 중.

2. **자동차 1차 협력사 도메인 정밀 적합**
   8D Report, PPAP, ECN, FMEA, MSA, APQP, HKMC SQ, EU CBAM, MSDS — 아진산업의 실제 협업 흐름과 1:1 대응.

3. **6개 기능이 서로 cross-link**
   Feature C 챗봇이 `regulation_qa` → D, `spc_status` → F, `compose_document` → B로 디스패치. 단일 챗 진입점에서 전사 워크플로 연결.

4. **정량적 ROI 추적 기반 마련**
   `/admin/analytics/roi` — LLM 비용 vs 절감 시간을 수치화. "실리"를 측정 가능하게 만든 것이 매우 적절.

### ⚠️ 약점 — 깊이의 함정

1. **D 모듈이 56 모듈로 비대**
   D1만 켜고 D2~D5는 flag로 끄는 상태. *"잘 만들었지만 운영 못 함"* 의 위험. 평가위원이 데모에서 비활성 화면을 보면 의문 발생 가능.

2. **시드 데이터 의존도**
   685건 에러 이력, 9개 크롤러 fallback `source_type="curated"`, SPC 5공정 합성 데이터. *"운영 시 정확도는 운영 데이터 누적 후"* 가 곳곳에 명시되어 있어, 평가에서 "실제 작동" 의심받을 여지.

3. **공식 인증키 의존**
   `LAW_GO_KR_OC`, `CUSTOMS_API_KEY`, `DART_API_KEY` 없으면 폴백. 시연 시 "키 발급 안 됨"으로 핵심 기능 비활성 위험.

**판정: 🟢 A- (취지 강력 부합, 데모 시 운영급/시드 구분 명확화 필요)**

## 2️⃣ 기능별 상세 평가

### 🅰️ Feature A — 인원 / 문서 검색

**실리·실무 (🟢 A)**
신입의 첫 마찰점("부품개발팀 과장 누구?")을 직접 해결. F5 마스킹 정책(내선·이메일 공개, 휴대폰만 마스킹)이 **사용자 시연 피드백을 반영한 산물**이라는 점이 실리 정신과 부합. W1~W8 + F1~F5 패치로 80%→100% 끌어올린 의사결정 흔적이 인상적.

**UIUX (🟢 A)**
- ⌘K 글로벌 명령 팔레트 — 어디서든 호출, 첫 접점으로 우수.
- 신입 온보딩 사이드 패널(`role_level ≤ 2`) — 사수 자동 추정, 5종 체크리스트.
- F4 본부 → 팀 드릴다운 강제 해제 → "팀이 어느 본부인지 모르는 신입" 케어.

**개선 권고**
- 검색 결과 0건 시 "인사관리팀에 문의" 안내는 좋으나, **검색 팁이 신입에게 명확한 행동 지침인지** 다시 검토.
- 조직도 트리맵(Plotly)이 모바일에서 어떻게 동작하는지 미검증.

### 🅱️ Feature B — 문서 작성 (Draft)

**실리·실무 (🟢 A) — Killer feature**
8D / PPAP / OEM 영문 이메일 / 주간보고 등 23종 문서 유형을 7포맷(DOCX·PDF·HWPX·ODT·XLSX·CSV·TXT)으로 즉시 출력. HWPX 정식 OWPML 구현은 한국 공기업·제조사 환경에서 결정적 가치. CC 자동 추천 3-tier + 품질 5기준 100점 채점은 **임원 보고를 자주 쓰는 부서장에게 강한 ROI**.

**보안 정책 — 매우 우수**
- `FEATURE_B_BLOCK_GEMINI=true` 기본값으로 사내 문서 외부 유출 차단
- 자동 안전망(Ollama 없을 시 차단 자동 해제)으로 운영자 실수 방지
- 양식 업로드 5MB 한도 + 메모리 추출 후 즉시 폐기

**UIUX (🟡 B+)**
- 강점: 3탭(작성/결과/이력), Liquid Glass, 5단계 진단 배너, SSE 토큰 실시간 출력
- 약점: 메타 입력 필드가 문서 유형마다 다름 — 신입 입장에서 "필수★ 표시는 있지만 왜 필수인지" 학습 곡선 존재. v4.0 B2 `VariableForm` 진행률 바가 이를 완화하나, 첫 사용자에게는 여전히 부담

**개선 권고**
- 문서 유형별 **"예시 보기"** 버튼이 결과 탭에 항상 노출 (현재 popover만)
- 신입 첫 사용 시 "휴가 신청서"처럼 가장 단순한 유형을 자동 추천하는 onboarding step

### 🅲 Feature C — AI 업무 도우미 (Onboarding Chat)

**실리·실무 (🟢 A) — 실리 경진대회 취지의 정확한 직격탄**
*"신입 6개월간 사수에게 묻기 어려운 질문 24시간 답"*

**2단계 응답 엔진** 설계가 뛰어남:
- 1단계 (룰, ~100ms): glossary → SOP 8종 → 협업 시나리오 5종 → 액션 8종 (룰만으로 70% 처리)
- 2단계 (LLM, 1-3s): 부서별 시스템 프롬프트 + 멀티턴 메모리(요약 압축으로 토큰 80% 절감)

부서별 응답 차별화(품질팀 vs 생산기술팀 vs 영업팀)는 도메인 깊이를 보여주는 핵심.

**UIUX (🟢 A)**
- C5 KB 자동 prepend (총무인사팀 4개 가이드) → 의도가 명확한 추천 질문 클릭 시 신뢰도 높은 답변
- C1/C2 라벨 단순화("부서 컨텍스트"→"부서", `세션 #A47-2026`→`대화 ● LIVE`) — 신입의 인지 부담 직접 감축
- 응답 메타(src / conf / latency)로 답변 신뢰도 시각화 — **AI 결과를 무비판 수용하지 않도록 유도**

**개선 권고**
- KB 자료가 **총무인사팀 4개만 MVP** — 시연 시 다른 부서 신입이 물으면 LLM only 응답. 평가 전 최소 5~6개 부서 추가 KB 작성 시급
- 👎 받은 답변의 root-cause loop가 분기별로만 검토되면 의미 없음 — 운영 SOP 명시 필요

### 🅳 Feature D — 법규 모니터링 (Compliance) ★

**실리 (🟡 B+)**
- 야심: 9개 외부 규제 자동 크롤링, RAG, What-if 시뮬, 학습경로, 결재워크플로, Jira sync, DART 공급망 발굴. **"전사 컴플라이언스 플랫폼" 비전**.
- 현실: P2 운영 기준에서 **D1만 활성** (`FEATURE_D_D1_ALERTS=true`), D2~D5는 모두 `false`. 56 모듈 중 약 1/3만 라이브.

**실무 (🟡 B)**
- 안전보건팀·품질보증팀: CRITICAL/HIGH 알람 SLA 5분/30분이 실질적 가치
- What-if 시뮬레이션, 임원 보고서 자동 생성, 학습경로 SCORM/xAPI export는 **운영 데이터 (DART API + 사내 ERP) 연결 없이는 데모 수준**
- 법적 판단 보호 disclaimer + 독립 검토 기록 요구는 매우 적절 — **AI를 법무 책임에 끌어들이지 않는 안전장치**

**UIUX (🔴 C)**
- /compliance 4탭 + 별도 라우트 3개 + 위임 룰 + 결재 chain + Jira webhook + 학습경로 export — **신입 첫 진입 시 압도됨**
- "법규 모니터" 탭은 일독 가치 있지만, "법규 업데이트"의 What-if는 신입에 무의미
- 변경 카드 클릭 → 영향 5차원 drawer(시설/계약/협력사/부서/판례)는 첫 사용자에게 정보 폭격

**개선 권고**
- **D는 권한 게이트로 명확히 가려야 함** — `role_level <= 2` 신입에게 사이드바에서 D 모듈 자체를 숨기거나, "법무·안전 담당자 전용" 라벨 노출
- 시연 시나리오를 D1(변경 감지 + 알람)으로 한정 + D2~D5는 "로드맵" 슬라이드로 분리
- /compliance 첫 진입 시 30초 가이드 투어 추가 권장

### 🅴 Feature E — 인사·관리자 패널

**실리 (🟡 B)**
신입/현직자에게는 무의미 (RBAC L4+ 한정). 그러나 **운영 가능성을 입증**하는 필수 모듈이라는 점에서 평가 가치 있음.

**실무 보안 (🟢 A) — 최상급**
- HttpOnly cookie + CSRF + refresh rotation
- bcrypt + 5회 실패 자동 잠금 + password_history 재사용 방지
- OIDC / SAML / LDAP IdP-first, 로컬 로그인은 SYS_ADMIN 2FA break-glass만
- hard delete 기본 차단 + `AUTH_ALLOW_HARD_DELETE=true` + SYS_ADMIN + 사유 + 확인 사번 4중 가드
- `feature-e-release-check` 자동 gate (74 endpoint surface, cookie wiring, default 계정 blocker)

> 이 정도 보안 hardening은 졸업작품 / 경진대회 수준을 훨씬 넘어섬. OWASP / NIST / RFC 9700 기준 명시한 것도 인상적.

**UIUX (🟢 A)**
3탭 + minLevel 게이트(4/4/5) — 권한 없으면 탭 자체 숨김. 깔끔.

**개선 권고**
- ROI 분석(/admin/analytics/roi)은 **시연 슬라이드에서 강조 추천** — 평가위원에게 "실리"의 정량적 증거
- "휴가 기반 임시 위임" 백로그는 실제 협력사 운영에서 자주 나오는 요청 — v5 우선순위 검토

### 🅵 Feature F — 설비 / 공정 AI (SPC)

**실리 (🟢 A) — 도메인 깊이 최고급**
Nelson 8 Rules(R1~R8) 가이드 + Cp/Cpk + Markov 연쇄 다음 고장 예측 + 금형 lifecycle XGBoost + MTBF + 매뉴얼 RAG + 685건 에러 이력 + 79개 동의어 사전.
**자동차 부품 1차 협력사의 생산기술·품질팀 평가위원에게 직격탄.**

**실무 (🟡 B+)**
- 생산기술·품질 부서: 🟢 A — 매뉴얼 검색, Markov cascade, Cpk 추세는 즉시 활용 가능
- 그 외 부서: 무의미
- 실 PLC 연결은 별도 작업 — release gate에서 "OPC-UA bridge는 외부 현장 커넥터 범위, `--require-live-plc` 옵션에서만 fail"로 honest. 평가에서 "실시간"이라 하면 합성 데이터임을 분명히 전달해야 함

**UIUX (🟡 B)**
- 8탭(개요 5sub + SPC + 에러 + 매뉴얼 3sub) — 신입에게는 외계어 ("Cpk가 뭐죠?")
- 그러나 79 동의어 사전이 "프레스가 안 돼요" → E102로 매핑 → 신입 친화 시도 명확
- 챗봇 연동(`spc_status` 액션)으로 **자연어 진입점 제공한 것은 매우 적절** — F 탭 직접 진입 부담을 C로 우회

**개선 권고**
- /equipment 첫 진입 시 "정비 담당이세요? / 신입이세요?" 분기 선택 → 단순화 뷰 제공
- SPC 차트의 Nelson 위반 클릭 시 **"이 R1 위반이 어떤 의미인지" 한 줄 설명**이 풍선으로 항상 뜨도록 (현재 annotation만)
- 매뉴얼 RAG는 ChromaDB 인덱싱 필요 — 시연 전 최소 2~3개 매뉴얼 PDF 인덱싱 필수

## 3️⃣ UIUX 종합 평가 (신입 첫 접점)

### ✅ 디자인 시스템 일관성 (🟢 A)

- **Liquid Glass v3.5** 캐노니컬 토큰: `lg-card`, `lg-pill`, `lg-btn`, `lg-eyebrow`
- 라운드 토큰 2/12/16/18/24/999px tier (6/4/3/8 금지)
- F1 폰트 위계 정렬 (56px → 28px), F2 한국어 어절 단위 줄나눔 (`word-break: keep-all`)
- **이모지 0건** + lucide stroke-width 2 통일 — 산업용 도구다운 진지함

### ✅ 마찰점 해소 노력 (🟢 A)

- F3 이름 검색 BUG, F4 본부→팀 드릴다운 해제, F5 마스킹 완화 — **시연 피드백 즉시 코드 반영**
- C1/C2 라벨 단순화, C4 사이드바 streaming BUG 격리
- **반복적 사용자 피드백 → 코드 → 라이브 배포** 사이클이 작동 중

### ⚠️ 진입 부담 (🟡 B)

- 6개 사이드바 모듈 + 각 모듈 4~8탭 = **첫 접점 정보 폭격**
- 신입에게 D(법규), E(관리자), F(설비)는 대부분 불필요

**개선 권고**: 사이드바를 `role_level` / `department` 기반 동적 노출. 신입(L1) 기본 화면은 C(챗봇) + A(검색) 2개만, 나머지는 "전체 모듈 보기" 클릭으로 접근.

### ⚠️ 모바일 / 현장 대응 (🟡 B)

- `/equipment/field` + manifest.webmanifest로 PWA 시도 있음
- IndexedDB offline queue 설계 우수
