# 🏥 MediWay — 병원 내 환자 동선 가이드 플랫폼

> "진료 끝났습니다, 가세요" — 그래서 어디로?

**MediWay**는 대형 병원에서 진료 후 환자가 다음에 어디로 이동해야 하는지 모르는 문제를 해결하는 **실내 네비게이션 및 동선 안내 플랫폼**입니다. 의료진이 진료 후 환자의 다음 동선을 앱으로 전송하면, 환자는 실시간으로 병원 내 경로 안내를 받을 수 있습니다.

## 1. 기(起) — 문제 정의

### 1.1 배경

대형 병원(상급종합병원, 종합병원)은 수십 개의 진료과, 검사실, 원무과, 약국 등이 여러 층과 건물에 분산되어 있습니다. 환자는 하루에 여러 과를 방문해야 하는 경우가 빈번하며, 진료가 끝날 때마다 "다음에 어디로 가야 하는지"를 스스로 파악해야 하는 상황에 놓입니다.

### 1.2 핵심 문제

본 프로젝트는 대형 병원 이용 시 환자가 겪는 두 가지 핵심 문제에서 출발합니다.

**문제 1 — 모호한 안내**

진료가 끝난 후 간호사가 "끝났습니다, 가세요"라고 안내하면, 환자는 이것이 **귀가해도 된다는 의미인지, 다른 과로 이동해야 한다는 의미인지** 판단하기 어렵습니다. 특히 복잡한 진료 과정(채혈 → 내과 → 영상의학과 → 원무과)을 거치는 환자일수록 혼란이 가중됩니다.

**문제 2 — 복잡한 원내 동선**

"3층 영상의학과로 가세요"라는 안내를 받더라도, 대형 병원의 복잡한 구조 속에서 해당 장소를 찾아가는 것 자체가 어렵습니다. 표지판이 있어도 건물 간 연결 통로, 엘리베이터 위치, 층별 구조 차이 등으로 인해 길을 잃는 경우가 빈번합니다.

### 1.3 문제의 영향

| 이해관계자 | 영향 |
|-----------|------|
| 환자/보호자 | 불안감 증가, 진료 지연, 특히 고령자·장애인·외국인 환자에게 심각한 불편 |
| 의료진 | 길 안내에 반복적으로 시간 소모, 본연의 진료 업무에 집중 어려움 |
| 병원 운영 | 예약 지연으로 인한 전체 진료 흐름 차질, 환자 만족도 저하 |

## 2. 승(承) — 현황 분석

### 2.1 기존 솔루션 분석

현재 한국 의료 IT 시장에 존재하는 솔루션들을 세 가지 카테고리로 분류하여 분석하였습니다.

#### 2.1.1 범용 의료 플랫폼

| 앱 | 주요 기능 | 실내 네비게이션 | 동선 안내 |
|----|----------|:-------------:|:--------:|
| 굿닥 | 병원 접수/예약, 비대면 진료, 병원 검색 | ❌ | ❌ |
| 똑닥 | 실시간 대기현황, 예약/접수 | ❌ | ❌ |
| 닥터나우 | 비대면 진료, 약 배달 | ❌ | ❌ |
| 나만의닥터 | 비대면 진료, 약국 연결 | ❌ | ❌ |

이 앱들은 "병원에 가기 전"과 "병원 밖"에서의 서비스에 집중하고 있으며, **병원 내부에서의 환자 경험은 전혀 다루지 않습니다.**

#### 2.1.2 대형병원 자체 앱

| 앱 | 주요 기능 | 실내 네비게이션 | 진료 후 동선 전송 |
|----|----------|:-------------:|:---------------:|
| 삼성서울병원 | 일정안내, 접수, 위치보기, 결제, 처방전 전송, 주차 | △ (정적 지도) | ❌ |
| 서울대병원 | 길찾기, 예약, 검사결과 조회, 입원 서비스 | △ (BLE 활용 시도) | ❌ |
| 보라매병원 | 진료예약, 결제 | ❌ | ❌ |

대형병원 자체 앱들은 위치 안내 기능을 일부 제공하지만, **정적 이미지 맵 수준**이며 실시간 턴바이턴 네비게이션이나 의료진-환자 간 동선 전송 기능은 부재합니다. 또한 각 병원별 개별 앱이므로 범용성이 없습니다.

#### 2.1.3 정부 PHR 서비스

**나의건강기록** 앱은 건강정보 고속도로를 통해 1,004개 의료기관의 진료기록(투약정보, 진료이력, 건강검진, 예방접종 등 12종)을 통합 조회할 수 있는 서비스입니다. 그러나 이 앱 역시 병원 내 동선 안내 기능은 전혀 포함하지 않습니다.

#### 2.1.4 해외 병원 실내 네비게이션 솔루션

해외에서는 BLE 비콘 기반 병원 실내 네비게이션이 이미 상용화 단계입니다.

| 솔루션 | 기술 | 도입 사례 |
|--------|------|----------|
| Kontakt.io | BLE + Wi-Fi, 1~3m 정확도 | MD Anderson, NYU Langone, Mount Sinai (미국) |
| Cogniteq | iBeacon + 네이티브 앱 | 유럽 종합병원 (환자 네비게이션 시간 30% 단축) |
| infsoft | BLE 비콘 + 보행자 관성항법 | University Hospital Basel (스위스, 2,500개 비콘) |
| Steerpath | BLE + 디지털 캠퍼스 | 다수 유럽 병원 (2~6주 내 설치 완료) |

**핵심 발견**: 한국에는 이러한 병원 전용 실내 네비게이션 + 동선 가이드 통합 솔루션이 존재하지 않습니다. 이것이 본 프로젝트의 시장 기회입니다.

### 2.2 법적·규제 환경 분석

본 프로젝트의 기능 설계에 영향을 미치는 핵심 법령을 분석하였습니다.

#### 2.2.1 의료법

| 조항 | 내용 | 프로젝트 영향 |
|------|------|-------------|
| 제19조 (정보 누설 금지) | 의료인은 의료업무 중 알게 된 타인의 정보를 누설·발표 불가 | 환자 의료 정보(진단명, 검사결과)는 앱에서 직접 다루지 않음 |
| 제21조 (기록 열람) | 환자 본인의 기록 열람 요청 시 의료기관은 거부 불가 | PHR 기능은 나의건강기록 연계로 대체 |
| 제21조의2 (진료기록 송부) | 타 의료기관 송부 시 환자/보호자 동의 필요 | 의료 기록 자체는 전송하지 않으므로 직접 해당 없음 |

#### 2.2.2 개인정보보호법

의료기관에서 수집한 개인정보는 수집 목적 범위 내에서만 사용 가능하며, 타 목적 사용 시 별도 동의가 필요합니다(제15조 제1항). 본 프로젝트에서 다루는 **동선 안내 정보("원무과 3층으로 이동하세요")는 민감 의료정보가 아닌 시설 이용 안내**에 해당하므로, 의료법상의 엄격한 진료기록 규제를 직접 받지 않습니다. 다만, 동선 데이터에서 간접적으로 환자의 진료과 방문 이력이 추론될 수 있으므로 **데이터 최소 수집 원칙** 및 **실시간 처리 후 즉시 삭제** 정책을 적용합니다.

#### 2.2.3 규제 대응 전략

본 프로젝트는 법적 위험을 최소화하기 위해 다음 원칙을 따릅니다.

- **의료 정보 비접촉**: 진단명, 검사결과, 처방 내용 등 민감 의료정보는 앱에서 직접 다루지 않음
- **동선 정보만 전송**: "다음 목적지: 원무과 본관 3층" 수준의 시설 안내 정보만 취급
- **데이터 비저장**: 동선 안내 데이터는 실시간 전송 후 서버에 저장하지 않음
- **명시적 동의**: 앱 최초 사용 시 위치 정보 활용 및 동선 안내 수신에 대한 명시적 동의 확보

## 3. 전(轉) — 해결 방안

### 3.1 솔루션 개요

MediWay는 **의료진용 웹/앱**과 **환자용 웹/앱**으로 구성된 양방향 플랫폼입니다.

```
┌─────────────┐       ┌──────────────────┐       ┌──────────────┐
│  의료진 앱   │──────▶│   MediWay 서버    │──────▶│   환자 앱     │
│  (간호사)    │       │  (동선 전송 허브)  │       │  (네비게이션)  │
└─────────────┘       └──────────────────┘       └──────────────┘
     QR 스캔              실시간 전송              경로 안내 수신
     동선 선택            데이터 비저장             2D/3D 지도 표시
     전송 버튼            푸시 알림 발송            턴바이턴 안내
```

### 3.2 핵심 사용자 시나리오

#### 시나리오 A — 진료 후 다음 동선 안내

```
1. 환자가 내과 진료를 마침
2. 간호사가 의료진 앱에서 환자의 QR코드를 스캔
3. 간호사가 다음 동선을 선택: [채혈실] → [원무과] → [약국] → [귀가]
4. 환자의 앱에 푸시 알림: "다음 목적지: 본관 2층 채혈실"
5. 환자가 알림을 탭하면 현재 위치에서 채혈실까지의 경로가 지도에 표시
6. 채혈 완료 후 자동으로 다음 목적지(원무과) 안내
7. 모든 동선 완료 시 "오늘 진료가 모두 끝났습니다. 귀가하셔도 됩니다." 표시
```

#### 시나리오 B — 병원 내 자유 네비게이션

```
1. 환자/보호자가 앱에서 목적지 검색: "외래 약국"
2. 현재 위치에서 약국까지의 최적 경로 표시
3. 층 이동이 필요한 경우 엘리베이터/에스컬레이터 위치 안내
4. 도착 시 "목적지에 도착하였습니다" 알림
```

#### 시나리오 C — 주차 위치 기록 및 정산

```
1. 환자가 주차 후 앱에서 [주차 위치 저장] 버튼 탭
2. 주차 층/구역이 자동 기록 (BLE 비콘 또는 수동 입력)
3. 진료 완료 후 앱에서 주차 위치까지 네비게이션 안내
4. 주차 정산 정보 표시 (진료 할인 적용 여부 포함)
```

#### 3.3.2 기술 스택

**웹 데모 (Phase 1)**

| 영역 | 기술 | 선정 이유 |
|------|------|----------|
| 프론트엔드 | React + TypeScript | 컴포넌트 기반 UI, 타입 안정성 |
| 실시간 통신 | Firebase Realtime DB / WebSocket | QR 매칭 후 즉시 동선 전송 |
| 인증 | Firebase Auth (익명 인증 포함) | 비회원 환자도 QR만으로 사용 가능 |
| 푸시 알림 | Firebase Cloud Messaging | 크로스 플랫폼 푸시 |
| 실내 지도 | Leaflet.js + Custom SVG Overlay | 병원 평면도를 타일맵 위에 오버레이 |
| 배포 | Vercel / Firebase Hosting | 무료 티어 활용, 빠른 배포 |

**iOS 앱 (Phase 2)**

| 영역 | 기술 | 선정 이유 |
|------|------|----------|
| UI | SwiftUI | 선언적 UI, 최신 Apple 생태계 |
| 3D 스캔 | ARKit + RoomPlan API | iPhone LiDAR 활용 실내 3D 맵 생성 |
| 실내 측위 | CoreBluetooth + CoreLocation | BLE 비콘 수신, Wi-Fi 측위 |
| AR 네비게이션 | ARKit + RealityKit | 카메라 뷰에 화살표 오버레이 |
| 네트워킹 | URLSession + Combine | 비동기 API 통신 |

### 3.5 실내 네비게이션 구현 전략

데모부터 실서비스까지 **4단계 점진적 고도화** 전략을 채택합니다.

#### Level 1 — 정적 경로 안내 (웹 데모)

- 병원 평면도 SVG 위에 출발지-목적지 경로를 하이라이트
- 층 이동 시 "엘리베이터를 타고 3층으로 이동하세요" 텍스트 안내
- 실시간 위치 추적 없음, 사전 정의된 경로 표시
- **구현 난이도: ★☆☆☆☆**

#### Level 2 — Wi-Fi 기반 대략적 위치 (앱 MVP)

- Wi-Fi 핑거프린팅으로 현재 층과 대략적 구역 파악 (정확도 5~15m)
- 보행자 관성항법(PDR)으로 이동 방향과 거리 추정
- "현재 2층 동쪽 구역에 계십니다" 수준의 안내
- **구현 난이도: ★★☆☆☆**

#### Level 3 — BLE 비콘 실시간 네비게이션 (파일럿)

- 병원 내 BLE 비콘 설치 (주요 분기점, 엘리베이터 앞, 진료실 입구)
- 1~3m 정확도의 실시간 블루닷 네비게이션
- 턴바이턴 안내: "10m 앞에서 우회전 → 엘리베이터 탑승"
- **구현 난이도: ★★★☆☆**

#### Level 4 — AR + 3D 네비게이션 (고급)

- iPhone LiDAR로 사전 스캔한 3D 맵 활용
- ARKit 기반 카메라 뷰에 화살표 오버레이
- Google Street View와 유사한 실내 3D 뷰 제공
- **구현 난이도: ★★★★★**

### 3.6 의료진용 인터페이스 설계

의료진(간호사) 앱은 **최소한의 터치로 동선 안내를 완료**할 수 있도록 설계합니다.

```
┌─────────────────────────────────────┐
│  MediWay Staff                   ☰  │
├─────────────────────────────────────┤
│                                     │
│  📷 [QR 스캔하기]                    │
│                                     │
│  ─────────────────────────────────  │
│                                     │
│  빠른 동선 템플릿                    │
│                                     │
│  ┌───────────────────────────────┐  │
│  │ 🔵 채혈 → 원무과 → 약국 → 귀가 │  │
│  └───────────────────────────────┘  │
│  ┌───────────────────────────────┐  │
│  │ 🟢 원무과 → 귀가              │  │
│  └───────────────────────────────┘  │
│  ┌───────────────────────────────┐  │
│  │ 🟡 영상의학과 → 원무과 → 귀가  │  │
│  └───────────────────────────────┘  │
│  ┌───────────────────────────────┐  │
│  │ ➕ 직접 경로 만들기            │  │
│  └───────────────────────────────┘  │
│                                     │
│         [ 전송하기 ]                 │
│                                     │
└─────────────────────────────────────┘
```

핵심 설계 원칙은 다음과 같습니다.

- **3탭 완료**: QR 스캔 → 템플릿 선택 → 전송 (총 3번의 터치)
- **자주 쓰는 동선 템플릿**: 해당 진료과에서 빈번히 사용하는 동선을 사전 등록
- **커스텀 경로**: 특수한 경우 POI를 직접 선택하여 동선 구성
- **전송 확인**: 환자 앱에 전송 완료 시 확인 표시

└── 피드백 반영 및 서비스 고도화

### 4.2 기대 효과

#### 환자 경험 개선

- 진료 후 동선 불확실성 해소 → 불안감 감소
- 병원 내 이동 시간 단축 (해외 사례 기준 약 30% 감소)
- 고령자, 장애인, 외국인 환자의 접근성 향상

#### 의료진 업무 효율화

- 반복적인 길 안내 업무 제거 → 진료 집중도 향상
- 동선 안내 표준화 → 안내 누락 및 오류 감소

#### 병원 운영 최적화

- 예약 지연(no-show, late arrival) 감소
- 환자 동선 데이터 분석을 통한 혼잡 구간 파악 및 공간 배치 최적화
- 환자 만족도 지표 향상
