## 1. 전체 비전 (2026 시장 맥락 갱신)

### 목표
1. **계약 병원 다수를 하나의 플랫폼으로 운영** — 공통 코어 + 병원별 브랜딩/설정
2. **환자에게는 "내 병원 앱"** — 로그인 후 소속 병원의 대시보드로 자연 진입
3. **의료진에게는 업무용 콘솔** — 소속 병원 범위 내에서 세션·계획 관리
4. **플랫폼 관리자(MediWay 운영사)** — 병원 온보딩·계약·감사

### 시장 포지셔닝 (v2 재정립)
**Target = 300베드 미만 중소·2차 병원.** 이 층은 똑닥이 깊이 파고들지 못했고, 상급종합병원의 자체 앱 스케일은 과잉. MediWay는 **"똑닥으로 커버 안 되는 원내 동선·세션·가족 대리에 특화한 화이트라벨 SaaS"**.

- **똑닥과 대립각 X** — 오히려 **똑닥 예약 데이터를 가져오는 연동**을 장기 로드맵에 두기
- **차별화 3축**:
  1. **원내 QR + 실시간 길찾기 + 세션** (경쟁사 대부분 단순 위치 표시)
  2. **고령자 퍼스트 UX + 가족 대리** (MyChart·똑닥 미지원)
  3. **검사결과 무기한 + 실손 청구 자동화** (세브란스·아산 약점 공략)

### 핵심 원칙 (v2 추가)
- **Single codebase, per-tenant config** — 병원별 fork 금지
- **데이터 격리는 보안 규칙으로 강제** — `hospitalId` 기반 RTDB 규칙
- **점진적 출시** — P1 완료 시점에도 단일 병원 모드가 깨지지 않아야 함
- **고령자 우선** — v2 신규 원칙. 모든 Phase에서 "이 화면을 70세 사용자가 쓸 수 있는가?"로 검증
- **규제 안전 마진** — 법무 경계(원격진료·의료광고·PIPA)를 넘지 않는 기능만
- **똑닥 학습** — "실시간 대기"는 차별화 아닌 TIG, 본전만 하고 넘어가기

### 2026 시장 가정 (내부 기록용)
- **똑닥**: 2024 IPO 후 B2B SaaS 확장 중, 중소병원 세일즈 경쟁자
- **나의건강기록(MyHealthway)**: 2025 대폭 확대, FHIR R4 API 안정화
- **비대면 진료**: 2024 만성질환·follow-up 영구 합법, 하지만 초진 제한
- **Live Activity**: 똑닥이 2023에 선점, **이제 TIG**
- **생성형 AI 환자 접점**: 2025-2026 대형 병원 파일럿 (증상 triage·진료 요약)
- **PASS·네이버·카카오 인증서**: 의료 본인확인 채널로 확산
- **Apple Watch / 삼성헬스**: 고령자 바이탈 연동이 새 차별점

### 범위
- 5개 Phase × 총 ~12-16주 (v1 대비 AI triage + Apple Watch 추가로 ~2주 확대, TTS·다국어 연기로 상쇄 일부)

## Phase 2 — 대시보드 셸 + 상단 탭 + 고령자 전제 (3주)

> **v2 변경**: 홈 위젯 **3개 상한**, **고령자 모드 토글을 시작부터 빌드**, 간단 모드를 기본값으로.

### 2.1 탭 구조 (v1과 동일 6탭)

| 탭 | 노출 조건 | 핵심 위젯 |
|---|---|---|
| 🏠 홈 | 항상 | 오늘 일정, 대기 순번, 응급 CTA (**최대 3개**) |
| 🏥 외래 | `features.appointments` | 예약·접수·대기·처방 |
| 🛏 입원 | `features.inpatient` + 입원 중 | 담당 의료진, 면회 예약 |
| 💊 건강검진 | `features.checkup` | 검진 예약, 결과 이력 |
| 🗺 안내 | 항상 | 기존 지도 + QR 흡수 |
| ⋯ 더보기 | 항상 | 결제·서류·가족·설정·**고령자 모드 토글** |

### 2.2 홈 탭 위젯 — v2 축소안
**3개 고정 + 병원별 1개 커스터마이즈 슬롯**

1. **오늘 일정** — 예약된 진료/검사 카드 (빈 상태 대응)
2. **대기 순번** — P3에서 실데이터, P2는 플레이스홀더
3. **응급실 CTA** — 항상 표시 (P4 F10이 여기서 태어남)
4. [선택] 병원 지정 위젯 1개 (공지 or 오늘의 팁 or 커스텀)

> **의도**: MyChart "너무 많다" 불만의 구조적 원인 제거. 위젯 추가 욕구는 "더보기"로 옮김.

### 2.3 고령자 모드 — **v2 신규: P2부터 전제**

- **더보기 → 고령자 모드** 토글 상시 노출
- CSS custom property + `.ui-senior` root class 기반 런타임 전환 (P4 F16 메커니즘 P2로 선행)
- P2에서 빌드: 토글 UX, class 주입 인프라, font-size root 조정
- P2에서 **모든 신규 컴포넌트는 ui-senior 클래스 하에서도 깨지지 않게** 설계
- 본격 고령자 전용 레이아웃(단순화 홈·큰 버튼)은 P4에서 완성

### 2.4 외래 탭 MVP (v1과 동일)
- 진료 시간표 / 예약 생성·취소 / 내 예약 목록
- 실시간 대기·접수·결제는 P3

### 2.5 안내 탭 (v1과 동일)
- 기존 `PatientPage.tsx` + `PatientMapBrowseView.tsx` + `PatientDashboard.tsx` 이관

### 2.6 더보기 탭 스켈레톤 (v2 조정)

### ✅ 완료 기준 (v2)

## Phase 3 — 고수요 편의 기능 (조정판) (3~4주)

> **v2 변경**: F6 축소, **F19 AI 증상 triage 신규 추가**, 주차 할인은 파일럿별 feature flag.

### 3.1 실시간 대기 순번 (F1) — v1 유지 (TIG)
- `/wait_queue/{hospitalId}/{department}/{date}/{queueNumber}`
- RTDB onValue 구독
- 홈 위젯: "내 앞 3명 · 예상 대기 ~12분"
- **Live Activity는 웹 Rich Push로 대체** (똑닥 ActivityKit 동등은 Phase 2.5 이후 Capacitor 래퍼 결정 시)

### 3.2 처방전 (F6) — **v2 축소**
- **삭제**: 약국 QR 발급·약국 선택 UI
- **유지**: 진료 완료 시 staff가 처방전 업로드 + 환자 다운로드
- **재도입 조건**: 2026 전자처방전 표준(건강보험심사평가원) 확정 후
- 지금은 **원문 PDF 저장 + 공유 링크 생성**만

### 3.3 결제 / 대리결제 (F8, F9) — v1 유지 (Must-have)
- **카카오페이 1차** (국내 MAU 최대)
- Firebase Functions + Webhook HMAC 검증
- **대리결제**는 MOAT 축 — 결제 링크 → 카카오톡 공유 → 보호자 결제
- 멱등성 키·서버 권위·PCI DSS 회피 원칙 v1 준수

### 3.4 알림톡 / Push (F5) — v1 유지 (Must-have)
- 카카오 비즈메시지 (알림톡) + FCM + SMS 3중 fallback
- 템플릿 5종 사전 심사
- 사용자 설정: 채널별 on/off

### 3.5 주차 할인 자동화 (F8) — **v2 조정**
- 어댑터 패턴 인터페이스만 P3에 정의
- **파일럿 병원별 feature flag** — 도심 중소병원(주차장 없음)은 완전 OFF
- 실제 구현은 파일럿별 계약 후

### 3.6 **NEW — AI 증상 triage (F19)**
- 환자 홈에서 "오늘 어떤 증상?" 입력 → **OpenAI/Anthropic API 호출** → 적정 진료과 추천
- 단순 라우터 수준으로 시작 (진단 ❌, 진료 추천 ⭕)
- 병원별 진료과 매핑 사전 구성 (`/hospitals/{id}/triage-map`)
- **명시적 고지**: "이 추천은 진단이 아니며 최종 판단은 의료진이 합니다"
- 사용 동의·audit log·속도 제한 필수
- 비용: 한 호출 ~$0.002 (GPT-4o mini 기준), 전환 효과 대비 매우 저비용
- 데이터: 증상 텍스트는 **서버 저장 금지**, API 콜 후 파기 (규제 안전 마진)

### 3.7 입원 · 건강검진 탭 (v1 유지)
- P2 스켈레톤을 실내용으로

### ✅ 완료 기준 (v2)

- 의료진 "다음 환자 호출" → 환자 Push 수신

- 주차 어댑터 인터페이스 정의 (구현은 파일럿별)

## Phase 4 — 접근성·가족 대리·OAuth (조정판) (2~3주)

> **v2 변경**: TTS 축소, **가족 대리를 MOAT 1순위**, Apple Watch/삼성헬스 연동 추가, 네이버 OAuth 연기.

### 4.1 고령자 모드 완성 (F16) — v1 유지, P2 기반 확장
- P2에서 깐 토글·CSS 인프라 위에:
- **전체 폰트·버튼 스케일 조정** (root font-size 18px → 22px)
- 홈 위젯 **4개 → 2~3개**로 더 단순화 (예약·안내 우선)
- 단어 축약: "비대면 진료" → "집에서 진료", "진료 예약" → "병원 예약"
- prefers-reduced-motion·색대비 AA 기준 충족

### 4.2 음성 길안내 / TTS (F17) — **v2 축소**
- **핵심 경로만** — 지도 길찾기 시 Web Speech API
- "다음: 엘리베이터에서 좌회전 · 15미터" 수준으로 제한
- **삭제 또는 연기**:
  - 앱 전역 TTS (홈 위젯 읽기 등)
  - Cloud TTS 서버 백업 (품질 이슈 없을 때까지 대기)
- 사용자 동의·명시적 트리거 원칙 유지

### 4.3 **🔥 가족 대리 (F7)** — **v2 MOAT 1순위**
- **영업 Top 3 셀링 포인트로 격상**
- "가족 추가" → JWT 초대 링크 (10분 만료·일회용) → 카카오톡 공유
- 권한 2단계:
  - **읽기** — 일정·대기 순번·검사결과(P5)
  - **대리** — 예약·결제 가능
- 개인정보 민감 항목(진단 상세)은 본인만 (옵션으로 해제)
- **모든 가족 대리 접근은 audit 기록**
- UI: 더보기 탭 → "가족" 섹션, 고령자 모드에서 홈 위젯으로도 노출 가능

### 4.4 OAuth 로그인 확장 (F15) — **v2 조정**
- **카카오 로그인** ✅ 필수

### 4.5 응급 버튼 (F10) — v1 유지, P2 홈 위젯에서 이미 배치

### 4.6 **NEW — Apple Watch / 삼성헬스 바이탈 연동 (F20)**

## Phase 5 — 고급 (재우선순위화) (지속·파트너십)

> **v2 변경**: 내부 우선순위 재배열, **실손 청구를 킬러 기능으로 승격**, 의료진 메시지는 법무 후 결정, 다국어 연기.

### P5 실행 순서 (v2 재정의)

1. **검사결과 무기한 보관 (F3)** — 가장 먼저 착수
2. **실손 청구 자동화** — 🔥 킬러 기능으로 승격
3. **PHR 연동 (F14)** — 파트너십 병행
4. **디지털 문진 (F4)** — EMR 벤더 확보 후
5. **의료진 메시지 (F11)** — **법무 검토 후 Go/No-Go**
6. **다국어 (F18)** — **Tier 2, 요청 들어올 때**

### 5.1 검사 결과 무기한 보관 (F3) — 🥇 P5 최우선

- EMR API 연동 (병원별 어댑터) 또는 staff 수동 업로드
- PDF·이미지·영상 → **Firebase Storage + AES-256-GCM**
- 메타데이터 Firestore/RTDB
- **타임라인 + 검색 필터** (종류·날짜·의료진)
- **"내 결과 다운로드 (전체)" — PIPA 준수**
- **차별화 포인트**: "세브란스 1년 제한을 넘어 **무기한 보관**" — 영업 1순위 메시지
- 가족 읽기 권한 연동 (P4 F7)

### 5.2 **🔥 실손 청구 자동화** — **v2 킬러 기능**

- **v1에서 한 줄 언급을 전면 승격**
- **사용자 고통**: 실손 청구 시 진단서·영수증·처방전 종이·팩스 접수 → 2-3주 지연
- **자동화 플로우**:
  1. 진료 완료 후 앱에 "실손 청구" 버튼 노출
  2. 진단서·영수증·세부내역서를 전자 묶음 PDF로 생성
  3. 사용자가 보험사 선택 → API 자동 제출 (삼성화재·KB·현대해상·메리츠 등)
  4. 청구 상태 푸시 알림
- **파트너십 복잡도**: 보험사별 API 상이, 6-12개월 협상
- **대안**: 파트너십 전에는 **보험사별 첨부 자료 자동 묶음 다운로드**부터 제공 (수동 제출이어도 고통 대폭 경감)
- **MOAT**: 성사 시 5년간 경쟁사 따라잡기 불가

### 5.3 PHR 연동 — 나의건강기록 (F14)

- 보건복지부·한국보건의료정보원 API (FHIR R4)
- OAuth2 + PKCE로 연결
- 타 병원 진료 이력 import → 통합 타임라인
- 2026 FHIR API 안정화 흐름에 맞춰 파트너십 성사 가능성 높음

### 5.4 디지털 문진 (F4)

- 동적 JSON Schema + 조건부 분기
- 병원별 문진 템플릿 (관리자 편집)
- 방문 1일 전 알림 → 제출 → 진료 중 의료진 화면에 노출
- **EMR 벤더 확보 후에만** 착수 (문진 결과가 의료진 워크플로에 들어가야 의미 있음)

### 5.5 의료진 메시지 (F11) — **v2 조건부**

- **v1에선 정식 포함, v2에선 법무 검토 선행**
- 한국 의료법 2024 개정에도 **"원격진료" 경계 모호**
- 게이트:
  1. 병원 법무팀 확인서
  2. 메시지 내용 제한 (처방·진단 키워드 자동 차단)
  3. 응답 SLA 명시 ("24시간 내" 등)
  4. PHI 최소 수집
- 게이트 통과 실패 시 **DROP** 또는 단순 Q&A 게시판으로 축소

### 5.6 다국어 (F18) — **v2 Tier 2 연기**

- **Tier 1 대형 병원(외국인 환자 다수)** 파일럿 있을 때만
- P5 기본 스코프에서 **제외**, 필요 시 별도 sprint

### 5.7 Apple Watch/삼성헬스 쓰기·실시간 (F20 확장)

- P4에서 읽기만 했던 것을 실시간 구독·의료진 공유로 확장
- 심박 이상 → 앱 알림 → 의료진 메시지 or 응급 버튼 트리거

### ✅ 완료 기준 (v2)
- 파일럿 병원 1곳에서 **검사결과 PDF 조회 (무기한)** 가능
