🧪 탭 전환 세션 보존 수동 체크리스트

이 페이지는 실 브라우저에서 수동으로 체크할 시나리오를 제시합니다. Mount-all + hidden 전략이 QR 스캐너와 폼 입력 상태를 탭 전환 중에 보존하는지 확인합니다.

사전 조건

  • 로그인 상태 · primaryHospitalId: demo
  • features.appointments=true 활성 (Firebase Console)

시나리오 A — 외래 폼 입력 보존

  1. /h/demo/patient/home?tab=appointments 접속
  2. "+ 새 예약" 클릭 → 폼 펼침
  3. 진료과 · 예약 시각 · 메모 입력 (저장 X)
  4. 상단 탭에서 "홈" 클릭
  5. 다시 "외래" 클릭
  6. 기대: 입력한 진료과·시각·메모 값이 그대로 보임

시나리오 B — 안내 탭 QR 스캐너 / 지도 뷰포트 유지

  1. /h/demo/patient/home?tab=guide 접속 → 지도 렌더 확인
  2. 특정 POI 클릭 또는 지도 zoom/pan 조작
  3. 상단 탭 "홈" → "안내" 순서로 전환
  4. 기대: 지도 뷰포트(확대·선택)가 이전 상태 유지
  5. 주의: html5-qrcode 카메라 스트림은 hidden (display:none) 상태에서 대부분의 브라우저가 일시 정지시킵니다. 탭 복귀 시 스캐너가 재시작되는지 확인. 만약 끊김이 확인되면 HospitalHomePage의 hidden 처리를 visibility:hidden + position:absolute 패턴으로 전환해야 합니다.

시나리오 C — 더보기 탭 고령자 모드 토글 지속

  1. /h/demo/patient/home?tab=more 접속
  2. "고령자 모드" 스위치 ON (화면 크게 변경 확인)
  3. 탭 "홈" → "안내" → "더보기" 순환
  4. 페이지 새로고침 (F5)
  5. 기대: 새로고침 이후에도 고령자 모드 ON 유지 (RTDB persist)

시나리오 D — URL 영속성

  1. /h/demo/patient/home?tab=guide 접속
  2. 탭 "외래" 클릭
  3. 기대: URL이 ?tab=appointments로 변경
  4. 브라우저 뒤로가기 버튼
  5. 기대: 탭이 "안내"로 전환

시나리오 B의 QR 스캐너 끊김 이슈가 확인되면 GitHub issue에 기록하고 C10 이후 폴리싱 때 처리합니다.
