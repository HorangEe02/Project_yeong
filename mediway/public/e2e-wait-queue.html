🧪 대기열 + FCM Push 수동 체크리스트

P3 C1-C5 실기기 검증용. 환자·의료진 두 개의 브라우저/디바이스가 필요합니다. 데모 병원 features.appointments=true, FCM 권한 허용 전제.

사전 조건

  • 환자 계정(예: user-patient)과 의료진 계정(user-staff, role=staff, hospitalId=demo) 각각 로그인 가능
  • 환자 디바이스: 알림 권한 "허용" (HomeTab 진입 시 useFcmToken이 자동 요청)
  • /user_fcm_tokens/<patientUid>/*에 토큰이 저장된 것을 Firebase Console에서 확인
  • 클라우드 함수 onQueueCall이 us-central1에 배포되어 있음

시나리오 A — 접수 → 위젯 순번 즉시 반영

  1. 환자: /h/demo/patient/home?tab=appointments 진입
  2. "+ 새 예약"으로 오늘자 예약 생성 (진료과: 내과, 시간: 지금부터 1시간 후)
  3. 예약 카드의 "접수" 버튼 클릭
  4. 기대: "접수됨" 뱃지 전환 + 홈 위젯의 순번 N번 · 대기 중 실시간 표시

시나리오 B — 의료진 Call Next → 환자 알림

  1. 의료진: /h/demo/staff/queue 진입 → 부서 "내과" + 오늘 날짜 자동 선택
  2. 대기열에 환자 순번 카드 표시 확인
  3. "다음 환자 호출" 버튼 클릭
  4. 기대 (의료진): 환자 카드 status가 "호출됨"으로 전환
  5. 기대 (환자 홈 위젯): 배경 강조 + "호출됨 — 진료실로 이동해 주세요" 문구
  6. 기대 (환자 디바이스): 5초 이내 시스템 알림 배너 수신 (FCM Push)
  7. 알림 미수신 시: Firebase Console → Functions → onQueueCall 로그에서 sent=N failed=0 확인

시나리오 C — 진료 시작 → 완료 전환

  1. 의료진: 호출된 카드의 "진료 시작" 클릭
  2. 기대: 상단 "진료 중" 카운트 +1, 환자 위젯도 "진료 중"
  3. 의료진: "완료" 클릭
  4. 기대: 카드 사라짐 (default: completed 필터링), 환자 위젯 "접수된 진료가 없습니다"

시나리오 D — 교차 병원 격리 (보안)

  1. 다른 병원 계정 (hospitalId=smch)으로 로그인
  2. DevTools 콘솔에서 fetch('https://mediway-demo-default-rtdb.firebaseio.com/hospitals/demo/wait_queue/내과/<today>.json?auth=<idToken>') 시도
  3. 기대: HTTP 401 permission_denied — 다른 병원 대기열 차단

시나리오 E — AI Triage (선택)

  1. 병원 features.aiTriage=true 설정 (Firebase Console / RTDB)
  2. 환자: 홈 탭에서 "AI 진료과 추천" 위젯 노출 확인
  3. "2일째 기침과 미열이 있어요" 입력 → "진료과 추천" 클릭
  4. 기대: 상위 3개 진료과 + 신뢰도 % + "진단 아님" disclaimer 표시 (5초 이내)
  5. 동일 사용자가 1시간 내 10회 초과 시도
  6. 기대: resource-exhausted 에러 — 시간당 10회 제한 확인

로그 확인 위치

  • FCM: Firebase Console → Functions → onQueueCall(us-central1) 로그
  • Triage: Functions → triageSymptoms(asia-northeast3) 로그 + /triage_audit RTDB 경로
  • 대기열 상태: RTDB /hospitals/demo/wait_queue/내과/<YYYY-MM-DD>
